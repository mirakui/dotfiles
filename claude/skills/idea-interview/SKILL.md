# Idea Interview

ユーザーが「アプリのアイデアがぼんやりある」状態を、AskUserQuestion による一問一答で拾い上げ、Obsidian Vault の `Idea/` 配下に Markdown として保存するスキル。

ユーザーは決め打ちで仕様を持っていない前提で動くこと。仕様を詰めるためのスキルではなく、**後で見返せる粒度で拾い上げる** ためのスキルである。

## Step 1: 最初のアイデアを自由記述で受け取る

選択肢化せず、自然言語で「どんなアプリ・サービスのアイデアですか？ぼんやりとしたままで構いません」と聞く。

理由: 最初の発話まで選択肢化するとユーザーの自由な発想を制約してしまう。ぼんやり段階の生の言葉を引き出したい。

## Step 2: 一問一答でヒアリングする

以下のトピックを **AskUserQuestion で 1 つずつ順番に** 出す。1 回の AskUserQuestion で複数質問を束ねない。

トピック（順番、必須ではなくスキップ可）:

1. アプリの形態（デスクトップ / ブラウザ拡張 / Web アプリ / モバイル）
2. 想定ユーザー（自分専用 / チーム内 / 一般公開）
3. コアな差別化価値（既存ツール ChatGPT/Notion 等で代替できない理由）
4. UI / 表示スタイルのイメージ
5. 起動方法 / 投入方法（ホットキー / メニューバー / 拡張 / Web）
6. 履歴・データ保存の方針
7. データソース（LLM 単体 / Web 検索 + LLM / API 連携など）
8. ステータス（ただの思いつき / そのうち作りたい / 近く試作 / 着手済み）
9. 仮タイトル

### AskUserQuestion 設計のルール

- **必ず「まだ考えてない」「まだ決めてない」相当の選択肢を 1 つ含める**。ぼんやり段階では「答えられない」が正解の質問が多い
- 選択肢は 3-4 個。各選択肢の `description` で具体的なシナリオを書く（抽象語の羅列を避ける）
- ユーザーが 2-3 連続で「まだ決めてない」を選び始めたら、それ以上掘らず **未決事項として記録して次のトピックへ進む**
- 既に最初の発話で答えが出ているトピックは飛ばす（例: 「Slack を見ているとき」と言っていたら「想定ユーザー」「形態」のヒントになる）
- 質問の総数は 6-8 個までを目安。それ以上は疲れさせる

## Step 3: タイトルを確認してまとめる

最後の質問でタイトルを確認したら、ヒアリング結果を以下のテンプレートにまとめる。

```markdown
---
created: <today YYYY-MM-DD>
status: idea
tags: [idea]
---

# <タイトル>

## サマリー
<ヒアリング結果を自然な日本語で 1-2 段落>

## 課題 / モチベーション
- ...

## 想定ユーザー
- ...

## コアな価値（差別化）
- ...

## 機能メモ
- ...

## 未決事項
- <「まだ決めてない」項目をここに集約>

## 参考
- <ユーザーが言及したリファレンス・既存ツール>

## ステータス
<回答>
```

注意:
- **内容が無いセクションは丸ごと削除する**（空の見出しを残さない）。Obsidian で開いたときに空セクションが並ぶと汚い
- **「未決事項」は丁寧に書く**。ぼんやり段階のアイデアは未決の方が多く、ここが後で再開する手がかりになる
- ユーザーが参考にあげた既存サービス・アプリは必ず「参考」セクションに残す

## Step 4: ファイルに保存する

- 保存先: `${HOME}/Documents/mirakui/Idea/<title>.md`
- ディレクトリ `Idea/` が無ければ作成する
- ファイル名: タイトルから生成。日本語そのまま OK（Obsidian なので日本語ファイル名問題なし）
- 「(仮)」のような括弧表記はファイル名からは除き、H1 タイトルにだけ残す
- 既存ファイルと衝突したら **上書きせず、別名を AskUserQuestion で確認する**

理由: Obsidian Vault は永続的な個人ナレッジベースなので、勝手な上書きは過去のアイデアを失わせる。

## Step 5: 完了報告

Markdown リンク形式で保存先を示し、ヒアリング結果のサマリを箇条書きで提示する。

報告フォーマット例:

```
保存しました: [Idea/<title>.md](Idea/<title>.md)

ヒアリング結果まとめ:
- **コア価値**: ...
- **ソース**: ...
- **想定ユーザー**: ...
- **履歴**: ...
- **ステータス**: ...
- **未決**: ...

追記・修正したい点があれば言ってください。次のアイデアも同じ流れで受け付けます。
```

最後の一文（追記受付）を入れることで、ユーザーが思い出した追加情報を後から差し込みやすくする。

## 注意

- **「ぼんやり」を尊重する**。決め打ちを強要しない
- 技術スタックや実装詳細を深追いしない。ユーザーが自発的に話したときだけ拾う
- このスキルは Obsidian Vault `${HOME}/Documents/mirakui/` 前提で動く。Vault のパスが変わった場合はスキル本文を更新すること
